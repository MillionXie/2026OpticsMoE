# LightGen2 推理工程导读

这个文件夹是供 Google Drive 交付和审阅的独立推理工程。输入视频后，程序完成四帧采样、视觉特征提取、两级路由与专家、两次光场传播和最终 MOS 读出。光场可视化工具记录同一次前向传播中的输入场、相位、传播结果和探测强度。

建议按 `README.md`、`infer.py`、`configs/selected.json`、`model.py`、`tools/visualize_fields.py` 的顺序阅读。

## 为什么原T22里面还有assets

T22是作者侧研究工作区，包含实验复算、初始化、训练和核验材料。这里的独立推理工程通过 `LightGen.pt` 获取完整前向计算所需的张量。

以下大小按MiB列出，1 MiB等于1,048,576字节。

| T22中的文件 | 大小约为 | 内容和用途 |
|---|---:|---|
| `assets/vision.pt` | 1090.20 MiB | 2808条视频的冻结视觉特征，形状为2808×4×49×1024，供作者侧训练和全数据复算使用 |
| `assets/language.pt` | 0.15 MiB | 固定prompt的语言embedding及其身份记录 |
| `assets/front.pt` | 4.68 MiB | 提取的Qwen patch投影和位置张量，用于准备独立模型 |
| `assets/manifest.csv` | 0.52 MiB | 视频ID、原路径、2250/558划分及MOS标签 |
| `assets/training_only_teacher_predictions.pt` | 0.18 MiB | 作者侧TRAIN教师预测 |
| `assets/initialization/initialization.pt` | 26.59 MiB | 早期初始化权重，供作者追溯和复现 |
| `assets/initialization/simplification_parent.pt` | 26.59 MiB | 读出简化阶段的父权重 |
| `assets/initialization/config.json` | 小型JSON | 初始化版本记录 |
| `assets/example/` | 约3.15 MiB | 作者侧原始示例视频、四张采样图和输入身份记录 |

约1.065 GiB的 `vision.pt` 把原视频前端计算预先缓存下来，可减少作者侧反复计算前端的时间。公开推理时，程序直接从输入视频计算前端特征。`LightGen.pt` 已携带所需前端、语言embedding和任务层张量。

T22中 `runs/` 保存实验过程与原始结果，`tests/` 保存回归核验，`tools/` 还包含作者侧训练和分析入口。这些目录属于研究工作区。Google Drive交付入口是当前 `LightGen2` 文件夹。

## configs中每个字段是什么意思

### 当前推理目录的selected.json

该文件只有四个字段。

| 字段 | 含义 | 使用方式 |
|---|---|---|
| `checkpoint` | 配套PT相对工程根目录的位置 | 光场可视化据此找到权重 |
| `checkpoint_sha256` | 该PT的完整文件指纹 | 光场可视化读取前校验文件 |
| `architecture` | 独立推理格式和网络版本标识 | 对应当前PT的架构标识 |
| `model_parameters` | 注册模型参数的元素总数，当前为3,777,350 | 模型规模记录 |

`infer.py` 使用命令行 `--weights` 指定的PT。`tools/visualize_fields.py` 使用 `--profile` 指定的JSON定位PT并校验SHA。移动配套权重时，命令行路径与JSON中的路径应对应新的文件位置。

网络结构来自PT内的 `config`，权重张量来自PT内的 `model`。五等级分值、前端和prompt也保存在同一个PT中。改JSON里的参数数目或版本文字只会改变记录；网络创建由配套PT中的结构字段决定。

### PT中的推理结构字段

| 字段或字段组 | 作用 |
|---|---|
| `width` | token通道数，192 |
| `router_hidden` | 路由隐藏层宽度，128 |
| `readout_hidden` | 末端读出隐藏层宽度，32 |
| `prompt_length` | 固定文本token数，38 |
| `videos`、`frames`、`tokens` | 每光场16视频、每视频4帧、每帧49视觉token |
| `temperature` | 四专家softmax的温度 |
| `canvas`、`active` | 518×518传播画布和478×478有效区 |
| `wavelength_nm`、`pitch_um`、`distance_m`、`cutoff_deg` | 波长、采样间距、传播距离和传播频率截止角 |
| `alpha_eval` | 与所选权重绑定的光场调制混合系数，加载时由PT提供 |

这些字段与已学习权重、输入布局和光学传播共同定义当前前向计算。审阅时可对照 `model.py` 的 `ModelConfig`、`GlobalStage` 和 `LightGenTemporal` 阅读。

### 原T22中的另外两类配置

| 配置 | 作者侧用途 |
|---|---|
| `configs/selected.json` | 指向研究权重，记录架构、选中轮次、完成轮次、开发SRCC和槽位审计 |
| `configs/train.json` | 记录父初始化、学习率、轮数、教师权重、随机种子、选模区间和模型设置 |
| `paths.local.json` | 指向作者机器的特征缓存、manifest和前端文件 |

`train.json` 中的 `entrypoint` 指定作者侧训练脚本，`initialization` 绑定父权重及SHA，`refinement` 记录本轮优化设置。`model` 描述原实现的结构与训练扰动，`training_protocol` 记录组场和有效位规则。

独立推理PT导出时保留前向需要的结构字段。模型加载后，所有参数固定，程序在推理模式下运行。

前向采用 `torch.inference_mode()`。为保持与核验版本一致的浮点执行路径，参数沿用PyTorch构造时的属性。推理输出的 `requires_grad` 为 `False`，前向运算采用关闭梯度图的执行模式。

## LightGen.pt具体包含什么

推理PT由以下部分组成。

- `schema`和`architecture`标识当前独立推理格式。
- `config`定义选中网络的尺寸、路由温度和传播设置。
- `model`保存前端、prompt、两个router、两组四专家、两个global、frame merger、读出层及五等级分值。
- `metadata`记录上游模型、来源权重指纹、当前张量指纹、许可和评价身份。

原研究PT中的目标均值、目标标准差和分桶边界用于辅助训练或归一化记录。当前导出采用前向计算需要的张量，并记录与源PT的逐张量对应关系。MOS由五个softmax概率与已保存的等级分值相乘求和，等级分值约为28.62、40.79、52.96、65.13、77.30。

## 运行后会得到什么

在当前文件夹执行。

```bash
python -m pip install -r requirements.txt
python infer.py --weights weights/LightGen.pt --videos examples/demo.mp4 --output outputs/demo.json
```

示例的CPU预测约为47.5284。`outputs/demo.json` 为每条真实输入视频记录 `video`、`slot` 和 `MOS`。`slot` 是当前16视频光场中的0至15号位置。`outputs/` 是运行时产生的结果目录。

多视频推理可写成以下形式。

```bash
python infer.py --weights weights/LightGen.pt --videos a.mp4 b.mp4 --device cuda --output outputs/mos.json
```

视频按给出的顺序组场，末组从输入列表开头循环补齐。同一视频的槽位和邻近视频会影响相干光场，因此复算时应固定列表、顺序和分组。

## 可视化和results的用途

```bash
python -m pip install -r requirements-visualization.txt
python tools/visualize_fields.py --profile configs/selected.json --videos examples/demo.mp4 --out outputs/fields
```

绘图需要操作系统中可供Matplotlib使用的Arial字体。选择一个新的输出目录。此命令生成两级光场图、复数场NPZ、采样帧预览、单槽位详细图、路由JSON、逐槽位预测CSV和校验清单。补齐槽位在CSV中标为 `valid=false`。

| results中的文件 | 内容 |
|---|---|
| `phase_masks.png` | 已选权重的相位示意 |
| `optical_expert_share.png` | 两级专家选择份额 |
| `global_ablation_summary.csv` | 控制结果的均值与样本标准差 |
| `global_ablation_seeds.csv` | 各随机种子的结果 |
| `global_ablation_protocol.json` | 控制条件和统计定义 |
| `global_ablation.png` | 上述CSV的已绘制版本 |
| `phase_controls.json`、`propagation_controls.json` | 相位替换、恒等传播的参考结果 |
| `reference_metrics.json` | 当前模型和电子对照的参考指标及评价口径 |

这些参考结果供阅读和绘图使用。新视频的MOS由当前PT和视频前向计算得到。已有CSV的重绘命令如下。

```bash
python tools/plot_global_ablation.py --summary results/global_ablation_summary.csv --output outputs/ablation.png
```

## 版本和交付

`LightGen2` 是审阅和Google Drive交付目录。T22的打包脚本从这里读取推理源码，生成发布镜像和 `LightGen2.zip`。`MANIFEST.json` 记录源码commit、权重来源、导出张量和所有交付文件的SHA。

Git保存源码、配置和文档。权重、示例视频及结果图片通过完整发布包与SHA清单传输。GitHub中的T22保留作者侧研究代码，Google Drive接收当前独立推理目录或其ZIP。
