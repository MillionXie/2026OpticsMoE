# 2026-09-12 SDK 实测记录

设备：SHS-202-M / Flex I/O Quad CXP-12 Enhanced，Mono8 1920×1080。夜间暗房，无 SLM、无测试照明。SDK 无 GUI/加密狗取图成功。

|检查|实际结果|边界|
|---|---|---|
|曝光 100/500/1000/3500 μs|各 3 帧；回读一致；PNG 像素一致；完整帧|只验证控制/传输，未认证照明下的线性|
|Black / White / VStrip|各 2 帧；0 / 255 / 0～224|是相机内置数字图，非真实光场|
|Gain_X1/X2/X4/X8|设置、回读、拍摄和恢复成功|暗房，不据此判断放大倍数或 SNR|
|1000 fps 档，曝光 100 μs|取 200 帧，主机复制+解码约 654.8 帧/s，记录的 frame ID 无跳号|不是证明传感器无任何丢失；不含存图/SLM/推理|
|2250 fps 档，曝光 100 μs|取 200 帧，主机约 405.0 帧/s，667 个 frame ID 跳号|不能用于满速无丢帧实验|

最高帧率下，接口曾拒绝把曝光直接恢复到其报告的上限 444.2 μs。已增加“临时降帧率 → 恢复曝光 → 恢复旧帧率 → 回读校验”的恢复逻辑。原始失败报告保留在 `results/benchmark_2250`，不覆盖为成功；新复测单独保存。

本工程逐张播放默认 100 fps 和 200 ms SLM settle，是保守联调设置。后续需接入实际光路测旧帧、稳定时间、曝光响应，并验证可用的同步触发方式。不能将这次短测的主机吞吐当作端到端光学加速比。

证据在师弟电脑本工程 `results/camera01`、`digital_*`、`gain_*`、`benchmark_*`；部分 JSON/样图已同步至本地同名目录。每张图记录曝光、帧率、增益、帧 ID、时间戳、完整性和 SHA。

测试代码：旧 ABO 的 47 项轻量回归（46 通过、1 跳过），另在正常 PyTorch 环境通过 4 项模型放置测试；新 SDK ABI/解码/参数恢复单元测试独立运行。没有训练或改动模型权重。
