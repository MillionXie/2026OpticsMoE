# LGVQ 时间质量评价：任务能效与计算能效完整说明

## 1. 本说明采用的唯一运算口径

全文统一采用：

```text
1 MAC = 1 次乘法 + 1 次累加 = 2 OP
1 GMAC = 10^9 MAC
1 TOP = 10^12 OP
TOPS = 每秒完成的 10^12 OP
TOPS/W = TOP/J
```

## 2. 比较对象与统计边界

### 2.1 共同任务

- 数据集与指标：LGVQ 时间质量评价，Temporal SRCC。
- 工作负载：16 个视频，每个视频抽取 4 帧。
- Ours：16 个视频的 64 帧被编码进一幅 `478×478` 有效光场，六次光传播均并行处理这幅光场。
- Qwen3VL：16 个视频按当前保存的基线协议运行；每视频 4 帧、每帧 `448×448`。
- 任务性能：Ours SRCC `0.8044`；Qwen3VL SRCC `0.7663`。

### 2.2 推理边界

Ours 计入：

1. 六次物理相干全场传播；
2. CCD 后的神经网络非线性读出；
3. 并行电子残差网络；
4. Bridge 中的神经网络层；
5. 最终时间质量任务头。

Qwen3VL@A100 计入：

1. 从第一个 Vision Transformer Block 输入开始；
2. 24 个 Vision Block；
3. Vision 后处理与 merger/deep-stack；
4. 28 个 Language Block；
5. 完整词表投影；
6. 五质量词读出与连续分数输出。

双方均不计入原始 MP4 磁盘读取、视频解码和通用数据加载。Ours 在线推理使用预先生成的 Qwen 边界特征。

## 4. Ours 的运算量

### 4.1 六次光传播

有效光场的空间模式数为：

```text
N = 478 × 478 = 228,484
```

一次自由空间传播被视为从全部输入空间模式到全部输出空间模式的稠密线性变换：

```text
单次传播 MAC = N × N
               = 228,484 × 228,484
               = 52,204,938,256 MAC
```

六次传播之间存在 CCD 探测、非线性和重新编码，不能合并成一次线性传播，因此：

```text
六次传播 MAC = 6 × 52,204,938,256
             = 313,229,629,536 MAC
```

按 `1 MAC = 2 OP`：

```text
光学 OP = 313,229,629,536 × 2
        = 626,459,259,072 OP
        = 0.626459259072 TOP
```

### 4.2 电子神经网络部分

电子部分按实际 Linear/Conv 张量形状以及真实调用次数统计 MAC。

#### 帧级 CCD 非线性读出

线性层作用于 `[64,49,96]`，输出 `[64,49,192]`：

```text
单次 MAC = 64 × 49 × 96 × 192
         = 57,802,752 MAC
调用 2 次 = 115,605,504 MAC
```

#### 视频级 CCD 非线性读出

线性层作用于 `[16,42,96]`，输出 `[16,42,192]`：

```text
单次 MAC = 16 × 42 × 96 × 192
         = 12,386,304 MAC
调用 2 次 = 24,772,608 MAC
```

#### 帧级并行电子残差

```text
Depthwise Conv MAC =  15,052,800
Pointwise Conv MAC = 115,605,504
单次合计          = 130,658,304 MAC
调用 2 次         = 261,316,608 MAC
```

#### 视频级并行电子残差

```text
Depthwise Conv MAC =    645,120
Pointwise Conv MAC = 24,772,608
单次合计          = 25,417,728 MAC
调用 2 次         = 50,835,456 MAC
```

#### Bridge 神经网络层

```text
frame_merger   = 4,718,592 MAC
serial_field   = 7,225,344 MAC
router_width   =   688,128 MAC
router_frames  =   200,704 MAC
合计           = 12,832,768 MAC
```

#### 最终任务头

```text

language projection  =  4,718,592 MAC

```

#### 电子部分汇总

| 电子组件 | 总 MAC |
|---|---:|
| 帧级 CCD 非线性读出，2 次 | 115,605,504 |
| 视频级 CCD 非线性读出，2 次 | 24,772,608 |


激活、归一化、池化、Softmax、索引、张量排版、CPU/GPU 搬运和文件 I/O 不计入 MAC-derived OP。并行残差不增加关键路径时间，但实际执行了运算并消耗能量，所以保留在运算量中。

### 4.3 Ours 总运算量

```text
总 OP = 光学 OP + 电子 OP
      = 626,459,259,072 + 1,125,138,432
      = 627,584,397,504 OP
      = 0.627584397504 TOP
```

## 6. 任务级速度与任务级能效

### 6.1 视频吞吐率

Ours：

```text
16 / 0.008660 s = 1,847.575 视频/s
```

Qwen3VL@A100：

```text
16 / 1.200053 s = 13.333 视频/s
```

完成相同 16 视频工作负载的速度提升：

```text
1200.053 ms / 8.660 ms = 138.574 倍
```

这是批次吞吐速度提升。Ours 的 16 个视频并行完成，因此不能把 `8.660/16=0.541 ms`称作单视频响应延迟；每个视频的批次响应延迟仍为 `8.660 ms`。

### 6.2 每视频平均能耗

Ours：

```text
1.162 J / 16 = 0.072625 J/视频
```

Qwen3VL@A100：

```text
103.784 J / 16 = 6.4865 J/视频
```

能耗降低比例：

```text
(103.784 - 1.162) / 103.784 × 100%
= 98.8804%
≈ 98.9%
```

### 6.3 任务级能效

任务级能效使用“完成的视频数/能量”：

```text
Ours       = 16 / 1.162   = 13.7694 视频/J
Qwen3VL    = 16 / 103.784 = 0.1542 视频/J
```

任务级能效比：

```text
13.7694 / 0.1542 = 89.315 倍
```

因此应写：

> Ours 的任务级能效达到 Qwen3VL@A100 基线的约 89.31 倍；平均每视频能耗降低约 98.9%。

`视频/J`等价于本任务中的`samples/J`或`inferences/J`。它衡量单位能量能完成多少个视频质量评价任务，明确与任务和批量协议相关。

## 8. 光学子系统单独统计

每次光传播硬件时间为：

```text
SLM 刷新 0.714 ms + 曝光 0.300 ms + 相机 0.0307 ms
= 1.0447 ms/层
```

六层：

```text
光学时间 = 6 × 1.0447 ms = 6.2682 ms
```

光学功率采用 `80.388 W`：

```text
光学能耗 = 80.388 W × 0.0062682 s
         = 0.503888 J
```

所以：

```text
光学吞吐率 = 0.626459259072 TOP / 0.0062682 s
           = 99.9424 TOPS

光学能效   = 0.626459259072 TOP / 0.503888 J
           = 1.24325 TOPS/W
```

这个数字只描述六层光学子系统，不包含 CCD 后的电子网络、Bridge 和任务头；不能与完整系统的 `0.5401 TOPS/W`混为一谈。

### PS 点积的精确公式里会出现“减 1”

长度为 `K` 的点积为：

```text
y = x1*w1 + x2*w2 + ... + xK*wK
```

如果只数最基本的标量算术，它包含 `K` 次乘法和 `K-1` 次加法，因此：

```text
精确标量 OP = K + (K - 1) = 2K - 1
```

一个 `M×K` 矩阵乘一个长度为 `K` 的向量、产生 `M` 个输出时，精确标量操作数为：

```text
M × (2K - 1) = 2MK - M
```

但 AI 加速器、GEMM 和 TOPS 评测通常把每个 fused multiply-add/MAC 统一记作两次操作，因此使用：

```text
K MAC = 2K OP
```

本文为了与 A100 的 MAC-derived 运算量及常见硬件 TOPS 口径保持一致，统一使用 `1 MAC = 2 OP`，不执行“减 1”。不能对光学侧使用 `2K-1`，却对 A100 侧继续使用 `2K`，否则双方口径不一致。

对六次 `478×478` 光传播而言，两种写法的差异只有：

```text
6 × 478 × 478 = 1,370,904 OP
```

相对于光学侧的 `626,459,259,072 OP`仅为 `0.0002188%`。即使改用精确标量写法，完整系统计算能效也只是从 `0.5400898` 变为约 `0.5400887 TOPS/W`，不会改变任何结论。
