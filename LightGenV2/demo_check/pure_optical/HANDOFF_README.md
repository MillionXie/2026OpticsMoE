# RGB/SAR分类：动态四支路MoE与整孔径D2NN

本包对应2026-09-16已完成的无电子分类支路试验，只提供动态四支路MoE和整孔径两层D2NN。
`models.py`定义两种架构，`run.py`训练/验证，`prepare.py`重建数据，`optics.py`为原角谱传播器。
无需原工程、Qwen或其他任务代码。仅相位是可训练参数。

| dynamic_four | 45.00% | 34.70% | 39.85% | 15 |

20轮。`reported_results.json`保留这两个模型的原始结果及权重摘要。打包仅整理依赖和运行入口，
没有重新搜索参数；本包默认只运行上述两个模型，原试验还运行过一个固定四支路消融组。

## 相对师弟原混合模型的改动

1. 移除Qwen特征、电子输入投影、电子残差、电子分类头和α，改用原图像的固定振幅编码。
2. 移除两层之间的探测、电子特征变换和重新加载；主光路在两层间保留复场。
3. 四个空间支路放入同一518×518复场传播，不逐窗口独立传播后在软件中拼接。
4. 路由CCD能量占比直接作为功率份额q，输入振幅系数为sqrt(q)，避免概率与功率混用。
5. 移除共享预训练/分域专家训练/仅路由训练的阶段流程，全部相位联合训练；不加域分组辅助损失。
6. 输出改为10个固定CCD区域能量归一化，用目标类别NLL训练；没有可学习读出头。
7. 仅保留水平翻转，不对SAR使用色相/饱和度扰动。保留原空间划分，使用固定均衡子集做初试。

因此这是新协议，不能将它与旧混合模型的数值差单独归因于去掉电子残差。

## 数据和张量

类别0—9依次是AnnualCrop、Forest、HerbaceousVegetation、Highway、Industrial、Pasture、
PermanentCrop、Residential、River、SeaLake；以附带`SPLIT.json`的标签为准。域0=RGB，域1=SAR。
沿原空间分组划分，从每类训练/验证集合分别按pair_id固定哈希顺序取300/100对，RGB和SAR一起保留。
训练255个空间组、验证74个空间组，组不重叠。测试图像不进入本协议。

RGB为64×64中心裁56×56。SAR按照同地点MS图像的地理参考重投影到56×56，双线性插值；
各VV/VH通道按单图1%/99%分位裁剪，再按固定均值[-12.59,-20.26]和标准差[5.26,5.91]
的±2σ映射到[0,1]，第三通道取前两者均值，量化到uint8。MS只提供地理参考，不进入分类输入。

模型输入`[B,56,56,3] uint8`→除255→各通道双三次插值112×112→
按`[ch0,ch1;ch2,zero]`排成224×224振幅→主光路总功率归一化为1。
训练水平翻转发生在通道拼图之前，两种模型的样本顺序、翻转随机数相同。

动态MoE：四块224×224专家相位、中心间距254、有效区478×478；按sqrt(q)加载四份输入，
全画布传播→478×478全局相位→再传播→固定CCD读出。四支路全部激活，不能解释为top-k路由，
也不是四个独立类别预测加权。路由器另用224×224相位、一次传播及4个60×60探测窗口。
路由探测、归一化和SLM控制仍有电子操作，不能称为完全被动全光系统。

D2NN：同一224×224编码插值到478×478并保持总功率，经过两块478×478相位和两次传播，再固定读出。
传播画布518×518、λ=532 nm、像素17 μm、每次距离10 cm；10个32×32分类探测窗口。
窗口中心、相位参数化、传播内核均在代码中固定并与原run一致。

## 训练和使用

在独立Python 3.11环境安装PyTorch 2.6.0 CUDA 12.4版，再安装`requirements.txt`；
原运行的完整版本见`training_environment.json`。运行需要CUDA GPU，默认batch32，在4090上验证。

```bash
pip install -r requirements.txt
python download_archives.py rgb ms sar --cache data/archives --workers 4
python prepare.py --root data
CUDA_VISIBLE_DEVICES=0 python run.py --phase smoke --out runs/smoke/check01
CUDA_VISIBLE_DEVICES=0 python run.py --phase train --data data/phase_only_v1/data.npz --out runs/simulation/train01
```

包内`data/SPLIT.json`已提供，三个大压缩包需要下载或放入`data/archives`。
若Hugging Face不可达，可将下载器SAR URL的域名换成hf-mirror.com；仍必须通过脚本内固定SHA256校验。
Windows PowerShell请先执行`$env:CUDA_VISIBLE_DEVICES="0"`，再运行`python run.py ...`。
输出目录必须不存在，以避免覆盖原结果。可以通过`--config /path/config.json`另开新协议。

Adam，lr=0.01、weight_decay=0，cosine到0.001；20轮，batch32，梯度范数裁剪1。
相位raw参数N(0,0.02²)，相位为2πsigmoid(raw)。主光路和路由相位联合训练，按验证准确率选模，
同分取较低NLL。相位层数量和传播几何在当前实现中固定；修改几何时需同步修改models.py，
不能仅改config中的尺寸或expert_pitch就认为几何已改变。

每组保存best/last_checkpoint.pt、逐轮history、验证逐样本预测、域指标和路由功率统计。
metadata记录配置、环境、源码/数据摘要；results汇总最佳验证结果。包内不附权重或原始图像。
原数据数组SHA256为`f543d0c9ce330272063a1669ebacef082b26dc77994ec76b251f477634e350bd`；
不同GDAL或压缩环境重建的数据容器摘要可能不同，需检查像素摘要和数据身份，不能只比较文件名。
`MANIFEST.json`列出所有包文件摘要，`PROVENANCE.json`记录打包及原训练版本。

两个模型使用不同照明拓扑，当前差值是完整架构差值，不能全部归因于路由。

应同时检查分类能力、探测效率、训练稳定性，并在新run中验证修改。单独增大学习率、训练深度或
改阈值都不保证性能改善。原固定四支路消融不在本包中，历史记录仍保留在原工程。
