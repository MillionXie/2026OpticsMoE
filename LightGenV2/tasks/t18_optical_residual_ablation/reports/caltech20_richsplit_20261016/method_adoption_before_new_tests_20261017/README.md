# 新TEST打开前：区分选轮、接续父模型与开发候选

这是对启动快照`1ce72fd5a`中“候选比较优先VAL”的补充澄清。登记时两个fresh100仍在训练，尚无各自新TEST；已存在的旧TEST观察与开发属性从未否认。人工此前明确“测试结果是最后最重要的”，并授权持续基于测试反馈开发、必要时更改类别/划分。当前继续固定本rich20类别/划分，不再移动角色。

1. **每条轨迹选checkpoint**：严格按已登记最高VAL EMA总体accuracy，同分自然NLL更低、再同分最早epoch。旧balancedNLL轨迹不改写；每条新参数digest测试最多一次，相同权重真实复用。不能按本条轨迹最高TEST epoch换checkpoint。
2. **额外训练选父模型**：两条fresh100完成各自科学/冻结TEST/CPU实际退出后，按VALaccuracy、自然NLL、最早选中epoch、名字序确定同一个fullLAST100父状态。后续两条短程都从这个相同raw/EMA/Adam19700恢复，不用哪个TEST更高来换训练父模型。
3. **面向人工目标报告/采用方法**：比较上述验证预选模型各自保存的真实TEST。TESTaccuracy更高者可作为开发候选；同分再看VALaccuracy/NLL，仍同分保留更早已有版本。原模型全部保留，所有负结果/实际预算也报告。这是跨方法的**TEST-informed development选择**，不是独立未见测试验收，也不是同预算纯光学残差因果结论。既不能把较高VAL直接当最终TEST提升，也不能因为本条TEST低而改选它未预选的历史epoch。

因此，三层意思不混用：训练/checkpoint和接续父模型规则在新TEST前固定；最终开发候选面对人工TEST目标比较，但明确测试已参与开发、不主张独立泛化。当前旧二/四/六层候选和冻结无残差100不因新训练被覆盖；TEST尚无增长时不得冒称已有增长。后续额外模型也必须各自独占科学/一次参数测试及保存预测核验通过。
