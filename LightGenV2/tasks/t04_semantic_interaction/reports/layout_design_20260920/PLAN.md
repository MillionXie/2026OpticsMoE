# OpenMoji 输入版式设计：待确认，不启动正式训练

## 当前问题与边界

现有合成器在224×224画布上用6×6隐式网格，中心间距32px；所有图标连同透明边缘一起缩成30×30。
对象随机取1～4个（add目标最多5个），随机位置和类别。因此外接框一样大不等于视觉大小一致，
苹果可能比房子显得更大，而少量对象又散在画面各处。问题在数据生成/渲染规则，不是光学mask排布。

这里保留16类OpenMoji风格，不用生成式绘图替代真实输入。所谓“真实比例”采用压缩的大小层次，
不是米制等比例：若房子与苹果严格等比例，224输入中苹果会消失。下面尺寸是人工设计参数，不是物理测量。

## 两个方案

| 方案 | A：保留6×6 | B：4×4、更舒展（视觉优先候选） |
| --- | --- | --- |
| 输入 | 224×224不变 | 224×224不变 |
| 中心坐标 | 32,64,96,128,160,192 | 40,88,136,184 |
| 最大可见图标边长 | 14～27px | 22～42px |
| 相邻最大图标最小框间距 | 至少5px | 至少6px |
| 图标处理 | 裁透明边，等比例缩放 | 相同处理，较大物体更易辨认 |
| 输出网格 | 仍36个位置 | 改为16个位置 |
| 网络影响 | 不改输出维度，仍需重训/评估新渲染分布 | 读出头、标签、坐标、评价及合成器一起改；不是仅改一个配置 |

两者不改光路、SLM物理ROI、光Router Top2、alpha>0.4和原未调制分量合同。
B的任务空间变小，可能变容易，不能将其分数直接与旧6×6的87.15%比较来宣称算法提升。
如果必须保持旧任务难度/输出合同，优先选A；若老师更看重输入可读性，可确认B后做一个独立数据版本。

## 确认后准备的数据规则

1. 使用alpha可见边界，不用透明PNG的整幅边界确定大小；始终保留宽高比。
2. 每类大小固定、与操作标签无关，暂不加随机缩放/透视/装饰背景，避免读图困难。
3. 以3～4个对象为主要构图，保留少量2对象，add后最多5对象；明确这是新分布，不声称保持原协议。
4. 加入紧凑布局与分散布局混合，不把所有样本限定在中心2×2；每个位置、关系方向、类别与操作须做频率审计。
5. 室外/动物/桌面组合仅作为部分样本，不以类别分组替代语义理解；保留充分跨组混合，防止类别组合成为任务捷径。
6. Source与Target使用完全相同的固定坐标与每类尺寸。添加/删除对象不能让其余物体自动居中、缩放或重新排版。
7. 拒绝遮挡、越界、关系冲突，编辑目标格必须合法；这些规则同样约束所有baseline，不能只替主模型挑漂亮样本。
8. 先生成固定种子的连续预览批次给人工确认，再生成全量train/test；去重、保存seed/manifest/渲染参数，旧数据和实测CCD不覆盖。
9. 论文示例提前固定选择规则，既展示成功也展示失败；Target和Prediction分开标，不用人工目标冒充预测。

## 训练与验证计划（用户确认视觉效果后执行）

先在CPU完成渲染、碰撞、关系、类别/位置分布检查。然后检查服务器空闲资源，只绑定1张GPU：
小数据10epoch检查梯度/相位更新与标签链路，再决定正式100epoch。我们的架构保持光路由和原头设计原则；
B仅必要地参数化输出网格，不能夹带TF/attention或新增电子支路。
对照必须使用同一新数据、相同输出合同和评估口径；原best直接测新版只能算分布迁移诊断，不能作为新版本性能。
每个run只保留best/last，完成/异常退出检查本任务PID和显存已释放，不停止其他人的进程。
