## 实際设计

- 庭院：房子高154px（画面高度68.75%），狗高29px；高比约5.31:1，狗在房子前方遮挡底部。
- 树下：树高156px，猫高25px；删除猫后重新合成其余完整图层，露出树干。
- 街角：房子高136px，汽车高26px，自行车高27px；公交车保持锚点、采用自身宽高比，比汽车更长。
- 所有尺寸是压缩现实层次的插画设计，不是实物测量值。门、树冠、车轮等原图内部比例不单独扭曲。
- 使用固定底边锚点、可见图标独立尺寸、显式z序，不再要求图像外接框塞在一个格子内。
- 背景不加渐变、阴影和新装饰对象；已有OpenMoji的原色和轮廓保持。
- 编辑只改变指定对象，其余对象不重新居中、不缩放；遮挡按实际alpha而非外接框面积计算。
- 规则阈值为各对象至少70% alpha面积可见；本轮8个source/target最低约80.7%。并非要求每个对象都必须被遮挡。

## 图像资产与复现

展示使用官方 OpenMoji 17.0.0 SVG，在1024px栅格化后裁透明边，再按尺寸渲染；不是把72px PNG直接拉大。
来源：https://github.com/hfg-gmuend/openmoji/tree/17.0.0/color/svg 。OpenMoji contributors，CC BY-SA 4.0。
图标资产与SHA见scene_manifest.json；原始SVG放本任务dataset/assets，不修改旧PNG。
仅这9个：1F333、1F3E0、1F415、1F33B、1F426、1F408、1F697、1F6B2、1F68C。

安装到独立环境的依赖：Pillow、numpy、resvg-py==0.5.0。下载原图后从仓库根运行：

```powershell
python -m LightGenV2.tasks.t04_semantic_interaction.layered_scene_preview --svg-dir LightGenV2/tasks/t04_semantic_interaction/dataset/assets/openmoji-17.0.0-svg
```

未提供--svg-dir时可以用已有72px PNG检查逻辑，但不是本次清晰预览所用路径。图像显示相同轮廓设计，
SVG与旧PNG的精确像素并不相同，后续训练必须统一使用选定的SVG渲染器，不能仅在论文图中偷偷换素材。

## 正式实现前还要确认的变化

这是对象级场景合成，不再是原来的单层网格覆盖。原6×6类别头不能直接完整表达跨格/遮挡对象。
下一步应先确定可训练的对象/锚点与类别输出合同、固定或预测的尺寸/z属性，以及source场景是否为已知输入。
如继续使用已知source对象保留与背景恢复，必须明确披露；这是受约束的对象编辑，不是RGB-only自由图像修复。
现阶段不要将新目标传给旧模型合成器冒充预测，也不能直接套旧87.15%指标。

常规数据设计将保持16类，按场景内尺度层次渲染，并分无遮挡/轻度遮挡两档；不只复制这三个庭院模板。
应避免一个类别恒定背景或一个模板恒定操作的捷径，保证位置/方向/操作均衡，区分展示示例与固定测试集。
几组展示场景及目标在训练前固定，按同一渲染规则进入保留展示集，不按预测成功率事后筛选。

正式训练仍等视觉和输出合同确认后再启动，一次只用1张GPU，保留best/last，结束核验进程退出。
本轮只新增独立预览脚本及测试；原模型、旧数据、实测CCD与设备参数均未改动。
