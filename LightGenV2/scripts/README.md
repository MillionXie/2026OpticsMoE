## LGVQ历史算力统计入口

`calculate_lgvq_topsw_ops.py` 已按服务器原 temporal 版本归主线；原字节SHA及
本地独有 `--target` 扩展的恢复提交见
[来源记录](../../maintenance/storage/HISTORICAL_LGVQ_OPS_SOURCE_20261006.json)。
扩展未丢失，但当前入口不接受 `--target`，不把 temporal 工作量套给 Spatial。

该工具是旧16视频×4帧模型的 MAC 派生算力统计，不是新模型测速：
实数MAC按2 OP，478×478六次整场传播另列为稠密复数MVM等效量，复数MAC按8实数OP；
这不等于光学设备执行数字矩阵乘法，也不包含激活、归一化、池化、索引和softmax。
Qwen边界从视觉第0块到完整词表投影及质量读出，按16次batch1调用折算。
CLI中的时间/能量默认值为历史输入常量，不是本轮测量，不可直接用于当前模型论文表。
CPU测试仅检查小张量计数、组件调用倍数、分组和原版源码身份，不运行Qwen、CUDA或正式数据。

原工具会写输出目录（不拒绝已有目录）；不要对原报告执行main。
模型/数据及完整历史环境仍须独立核验，不能将源码归主线当作从零复现已完成。

## 历史baseline绘图交付

`build_baseline_plotting_bundle.py` 将已有的八项baseline逐样本报告整理为绘图包，
不推理或训练模型，也不是当前OpenMoji/ABO模型的指标生成器。
原本机源码已保存在Git提交 `8bef68b0adf880f05ad2bdda0ef02a52db57285e`；
其启动时删除已有delivery的行为已移除。当前必须明确传入 `--output` 的新目录，
可用 `--raw` / `--qwen-report` 指向原始证据树；已有输出、输入树内输出或缺少
必需报告均在写入前拒绝。失败的新输出可能留下部分派生文件，保留供诊断，
工具不会自动删除它们，也不提供强制覆盖选项。

历史报告位置是 `LightGenV2/reports/baseline_plotting_20260922/`，不随源码Git分发。
原49份delivery文件、原ZIP及所有服务器报告/测速仍保留。
统计函数和原版本区分完全保留：LSP逐关节较早结果与后续A100汇总不混合；
未计时样本保持空值；未测精确PT的任务不借用其他版本延迟。
首次只读核验未发现服务器主目录同名打包源码，因此它是本地交付工具归主线，
不是“服务器模型运行版本”的替换。原始运行身份仍以各任务报告为准。
7项合成CPU测试只验证覆盖拒绝、完整输入前检及旧处理规则，不证明全部原始报告
或模型资产闭包，也没有执行原包的main、重新绘图或更改性能数字。
