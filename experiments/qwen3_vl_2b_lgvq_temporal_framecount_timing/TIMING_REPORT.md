日期：2026-09-04

任务：每个视频使用一次 Temporal prompt，输出一个连续数值

要求补测 49 帧，因此最终六档表已包含其全量结果。

## 样本数是什么意思

LGVQ 固定划分共有 2,808 个视频：训练集 2,250 个、测试集 558 个。本次推理计时使用
全部 **558 个互不重复的测试视频**。

- 每档帧数均为同一批 558 个视频，每个视频只测一次，所以每行 `N=558`；
- 六档合计逐视频计时记录为 `558 × 6 = 3,348` 条；
- 两个训练集 shape warmup 样本不计入 N，也不计入表中耗时；
- 这不是抽取 558 帧，而是测量 558 个完整视频；每个视频分别请求表中的帧数。

测试视频的源文件分布为：8 帧 93 个、16 帧 186 个、24 帧 93 个、36 帧 93 个、96 帧
93 个。源视频短于请求帧数时，时间位置换算后的整数帧号允许重复；程序不会去重，因为
去重会改变原工程的模型输入。

## P95 是什么

P95 是 558 个逐视频总耗时的第 95 百分位数，表示约 95% 的视频不慢于该时间，最慢约
5% 会超过它。本报告用 NumPy 默认线性插值：排序位置为
`(558-1)×0.95=529.15`，即在第 530 与第 531 个样本（从 1 开始）之间插值。

P95 不是平均值、准确率或置信区间。例如 25 帧平均仅 773.266 ms，但 P95 为
1929.744 ms，说明均值低于 910 ms 并不代表 95% 的视频都能在 910 ms 内结束。

| 帧数 | 随机 seek+解码 | Processor | CPU→GPU | 完整 Qwen | Pool+Linear | 总均值 |
|---:|---:|---:|---:|---:|---:|---:|
| 25 | 557.863 | 62.112 | 10.604 | 142.432 | 0.243 | 773.266 |
| 36 | 853.029 | 81.342 | 14.105 | 184.746 | 0.259 | 1133.494 |
| 49 | 1154.196 | 106.086 | 18.664 | 252.985 | 0.243 | 1532.186 |

49 帧时，随机 seek、解码、裁剪和缩放约占总均值 75.3%，完整 Qwen 约占 16.5%。线性
读出头仅约 0.24 ms，不是瓶颈。总时间与阶段和之间的极小差额是 Python 胶水开销。

## 计时边界

每个数值都是一个完整视频抽完该档全部帧后的总时间，不是单帧时间：

```text
打开原始 MP4
→ 每个目标位置单独 CAP_PROP_POS_FRAMES + read
→ 65% 中心裁剪并缩放到 448×448
→ Qwen processor 与一次 Temporal prompt tokenizer
→ CPU→GPU
→ 完整 Vision tower + learned merger + Language backbone
→ 最后有效 token + Linear(2048,1)
→ 标量返回 CPU
```

模型加载和 warmup 不计入逐视频时间。batch size 为 1；没有使用顺序整段解码、并行
解码、帧/特征缓存、量化、`torch.compile` 或手动 FlashAttention override。
