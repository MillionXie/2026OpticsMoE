# 未见类别：这轮具体测什么

这轮把问题拆成三个可测的层次：原有固定mask能否直接迁移到新类别；Qwen换一组新类别参考图后，不反传能否生成有用的mask；少量新类别样本的梯度能否使专家适配。只比较直接相位优化与Qwen视觉空间生成，不加入CLIP或global生成，也不改变光路。

## 已完成的结果与判断

两组新十类、5/20-shot、三次支持抽样、两种方法，共24组适配、120轮，均已完成。下表为三次抽样平均Top-1/Top-3（%）；标准差与未适配成绩见完整结果。

| 任务与支持量 | 直接相位适配 | Qwen适配 | 直接Top-1适配增量 | Qwen Top-1适配增量 |
|---|---:|---:|---:|---:|
| A，5-shot | 33.10 / 61.37 | 31.20 / 62.70 | +2.73 pp | +1.03 pp |
| A，20-shot | 42.00 / 71.50 | 35.00 / 68.03 | +6.30 pp | −0.30 pp |
| B，5-shot | 31.57 / 58.17 | 30.53 / 58.70 | +3.03 pp | +0.23 pp |
| B，20-shot | 38.43 / 66.43 | 34.83 / 64.90 | +6.20 pp | +1.27 pp |

增量均相对本方法、同一支持抽样的源mask不更新基线。**当前Qwen生成方案能生成、能反传，但没有显示比直接优化更强的新类别适配能力。**直接组在四项设置的平均Top-1及适配增量均更高；5-shot下Qwen的Top-3略高，不应将结论扩大为所有指标都更差。三次支持抽样不是三个源训练seed，也不足以建立普遍或显著性结论。

仅换支持参考图、不反传时，Qwen相位相对源bank的RMS变化为0.0314–0.0373 rad；四项设置的平均Top-1变化依次为−0.07、0.00、+0.07、−0.20个百分点。这说明条件输入确实改变了输出，但本轮未显示有用的免反传适配。原生成器只在单一固定参考任务上训练，没有学过“不同任务支持集→不同有效mask”的跨任务映射；这一事实限制了实验解释，但尚未通过额外控制实验证明它就是低收益的原因。

如果后续要针对老师提出的“新类别直接生成”继续改进，更合适的下一项研究是让生成器在多个源类别子任务间进行条件训练，再用完全留出的类别评估；同时设置相同源数据和预算的直接相位迁移对照。这需要新的类别训练/验证/测试合同。本轮没有看到测试成绩后追改学习率或追加轮数，也没有将这一后续设想写成已完成结果。

全部正式运行实际使用同一张GPU5 RTX3090。A原本等待GPU2，因其持续被其他任务占用，A在尚无任何训练启动时改用B全部结束后释放的GPU5。改配记录见 [分配审计](20260909_unseen_formal_a_allocation.json)，独立回传校验见 [execution_transfer.json](execution_transfer.json)。未使用A100。

全部60轮/方法的训练循环均值为direct7.702秒、Qwen16.993秒；含审计/保存的epoch均值为7.808秒和17.447秒。每轮20个batch，源训练与检索评估成本未计入。Qwen B/5-shot/seed101运行检测到外部PID1185036，整组保留标记；本轮不能当严格独占GPU基准，也未显示训练循环加速优势。120轮冻结参数变化和所有导出embedding误差均为零，任务到expert及Qwen LoRA的检查梯度均非零。

## 数据与“未见”的范围

源模型使用第五轮CIFAR原十类：`[3,13,14,17,28,31,35,81,86,94]`。直接和Qwen分别继承自己在源validation上选出的best；源训练SHA为`c024b9280433f6e7fe31fc0122a1b8aadf342b38`。两者均从raw0、物理π开始源训练。

从其余90类按固定seed20260909打乱，预先取两组十类：

| 任务 | CIFAR原始fine ID |
|---|---|
| A | 22, 25, 50, 52, 60, 66, 68, 72, 77, 80 |
| B | 5, 18, 20, 21, 26, 32, 34, 55, 85, 91 |

A对应clock、couch、mouse、oak_tree、plain、raccoon、road、seal、snail、squirrel；B对应bed、caterpillar、chair、chimpanzee、crab、flatfish、fox、otter、tank、trout。

两个新任务之间也不重叠；每个任务单独做十类类别原型检索，本地标签映射为0–9，不把30个类别混成一次十类测试。类别名和完整样本身份保存在每个run的`split.json`。

查询与候选原型均限定为当前新十类；本轮没有评估新旧类别同时竞争、未知类别拒识或旧任务遗忘。

这里的“未见”是**未进入所用源模型的CIFAR任务训练**。冻结Qwen基座和Caltech warmstart可能已经学过相关视觉概念，本项目其他历史模型也曾在CIFAR全百类上运行；本轮未载入那些百类模型，但测试图不属于全新盲测。不能把这项实验说成预训练也未见过这些类别。

## 支持集和查询集

每个任务、每个抽样seed，从官方train选每类5张或20张支持图，总数50或200。三个支持seed为101、202、303。相同seed的5-shot嵌套于20-shot，两个方法使用完全相同样本；没有按结果挑类别或样本。

支持集同时用来构建gallery类别原型和做梯度适配，没有额外提供gallery或validation标签。每个类别的支持embedding取均值并归一化，与查询embedding比较。每个任务的查询是官方test中对应十类的全部1,000张图，每类100张。查询绝不进入支持集、参考图或梯度。

因此，5-shot到20-shot的变化不仅包含更多训练支持，也包含更充分的类别原型；应与同样支持量的“不更新”基线配对。Top-1/Top-3是正确类别原型排名，不是任意实例检索Recall@K。均匀随机排名的期望分别是10%和30%。

## 三种评估的含义

| 方式 | 使用新支持图做什么 | 更新参数 | mask |
|---|---|---|---|
| 源mask不更新，两方法都有 | 只建立新类别gallery | 无 | 各自源模型的固定专家库 |
| Qwen仅换参考图 | 每类固定一张支持图输入视觉生成器，同时建立gallery | 无 | 保持源模型offset，计算新的生成输出 |
| 少样本适配，两方法都有 | 建立gallery并计算检索loss | 直接组只更新expert raw；Qwen只更新视觉q/v LoRA和expert decoder | 100个更新步骤后导出固定库 |

所有查询共享同一专家库；Qwen不会读取当前query、当前batch或query标签。它仅在适配过程中不断从固定参考集生成mask，最终导出后可移除生成器。“仅换参考图”仍需要新任务的有标签支持集，不能称为完全无样本生成。

Qwen原输出为 `Gθ(参考图) − 固定offset`。直接换参考图并保留源offset，会同时改变输出的中心和空间结构；该项是原生成器的条件外推诊断，不代表已经做过跨任务元训练。

正式适配时，先将新条件重新居中：

```text
expert_raw = 源expert_raw
           + G当前参数(固定新支持参考)
           − G适配开始参数(同一固定新支持参考)
```

减去的初始输出缓存为常量，不随训练更新。因此，适配起点保持本方法的源mask，没有因换条件突然跳变；之后梯度能回到LoRA和decoder。直接组同样从自己的源expert继续更新。**这是迁移续训，起始相位不再是零；零初始化约束在源训练时已满足。**如果改成每个新任务重新归零光路，测量的会是另一种“从头学习/生成器先验”协议，不能混入这轮。

## 固定训练预算与控制变量

适配固定5轮，每轮20个PK batch，每batch十类各三张图，共100个优化步骤、3,000次支持图抽样。一个epoch不是遍历支持集一次。不使用数据增强；每轮使用配对随机种子。

两侧router、global、电子接口、电子分支、readout及融合参数全部冻结。四路融合系数仍为0.6。仅直接expert或Qwen视觉LoRA/空间decoder训练：direct学习率0.02，decoder为3e-4，LoRA为1e-4；AdamW weight decay为0，10步warmup，余弦最低倍率0.15，逐组梯度裁剪1。目标沿用监督对比、episode原型检索和相位DC正则；没有teacher蒸馏。

Qwen生成器仍只有视觉塔，q/v rank8 LoRA，保留14×14空间patch grid，二维decoder输出`[2,4,224,224]`。光电学生的Vision/Language路径保持原结构；这里没有生成global，global保留源模型值并冻结。

不用新任务query选择checkpoint。每组只有预先指定的初始评估、Qwen条件外推评估及末轮评估。`best_checkpoint.pt`在本协议中特指固定末轮，权重与last相同；不是按测试成绩选择“最好一轮”。

两方法继承不同的源模型，源电子权重和源mask也不同。冻结它们能排除适配过程中电子抢先学习，但不能消除源模型之间的差异。因此同时报告最终Top-1/Top-3，以及“适配后减去各自不更新基线”的配对增量。三次支持抽样的标准差不等于三个独立源模型训练seed的稳定性。

## 计时和证据

每轮CUDA同步后记录训练循环和含冻结/相位审计、checkpoint保存的epoch时间。源训练成本、加载权重、初始/最终检索及逐查询预测写盘不计入epoch；单独的进程墙钟时间在GPU执行审计中。Qwen多了一次条件外推评估，不能直接拿两组总进程时长当纯适配速度差。

同一新任务的全部方法/抽样放在同一物理RTX顺序运行，启动前检查占用并按完整UUID绑定，禁止A100；队列遇到其他进程会等待。GPU审计每5秒保存实际时间戳和PID，仍可能有外部进程在启动后进入同卡，相关运行须标记。CPU/磁盘为共享资源。

正式训练SHA为`0d854376cca29e16143ad1eb7762860770e59459`。每组保存源best的完整SHA256、数据文件哈希、支持/查询身份、固定新参考、初始重建误差、任务到expert/LoRA的梯度、冻结参数变化、逐查询排名和导出一致性。轻量产物通过SFTP和独立远端SHA256回传，best/last仅保留远端哈希，不进Git。

结果见 [完整结果](完整结果.md)、[配对适配增量](paired_adaptation_gains.csv)、[逐轮时间](epoch_times.csv) 和 [准确度图](unseen_accuracy.png)。所有运行命令统一在 [复现入口](../reproduction/README.md)。

判断标准是：不反传的条件外推是否稳定改善新任务检索；相同支持量、相同更新预算下，Qwen是否有一致的最终成绩或适配增量优势。生成出不同mask只证明输出发生变化，不能单独证明适配有效或预训练知识迁移成功。本轮不依照已看到的query成绩更改类别、轮数或学习率。
